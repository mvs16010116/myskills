# 主题④ 报表与打印开发

> 覆盖：U9C 报表体系（SSRS + UFRPT）、开发全流程、数据源与数据查询、字段扩展属性、查询条件、布局、发布与权限、打印模板、高频坑。
> 典型问法："做一个报表"、"报表打开没数据"、"查询条件不生效"、"打印模板怎么做"、"报表发布后看不到"。

---

## 1. 报表体系总览

### 1.1 技术栈

`【实测】` `【官方】`

U9C 报表**不是自研引擎**，而是架在 **Microsoft SQL Server Reporting Services（SSRS）** 之上的：

```
U9C 应用
   ↓
UBF 报表设计器（设计报表布局 + 数据源）
   ↓
SSRS（Microsoft SQL Server Reporting Services）← 实际渲染引擎
   ↓  UFRPT 扩展
业务数据库 / 其他数据库
```

| 组件 | 作用 |
|---|---|
| **SSRS** | 报表服务器与渲染引擎 |
| **UFRPT 插件** | U9 自研的 SSRS 数据扩展，注册后才能连 U9 数据源 |
| UBF 报表设计器 | 设计期工具，集成在 UBF Studio 中 |

> **重要**：UFRPT 是 U9 专有的 SSRS Data Extension。**没有正确注册 UFRPT，报表连不上数据源**（注册方法见 `references/environment.md`）。

### 1.2 报表设计器能力

`【官方】`

- **既可以设计报表，也可以设计打印模板**（同一工具，两种模式）
- 既可以**修改系统的报表模板**，也可以**完成自定义个性化的报表**
- 完成后**直接发布即可实时查询效果**

**两种模式的切换**：`【社区】`

在 UBF Studio 的 `IDEConfig.xml` 中：

- `True` → **打印、报表设计模式**
- `False` → **单据设计模式**

> ⚠️ **做报表开发前必须先切到报表设计模式**，否则界面上不出现报表相关菜单。

### 1.3 报表 vs 打印模板

`【社区】` 引自《U9研发体系（打印开发手册）》

| 维度 | 报表 | 打印模板 |
|---|---|---|
| 设计工具 | UBF Studio 报表设计器 | **同一工具**（打印设计模式） |
| 设计内容 | **数据设计 + 布局设计** | **数据设计 + 布局设计** |
| 数据来源 | 由报表数据源直接提供 | **打印数据不是由打印引擎生成，而是开发人员在运行期根据当前 UIModel 提取出来的** |
| 数据设计重要性 | 核心 | **不如报表那样重要**，但**打印模板发布时会检查模型完整性，如果不进行数据设计会报错** |
| 项目类型 | 报表应用项目 | 分析项目 |

> **关键差异**：报表的数据靠 SQL/实体查询直接取；打印模板的数据靠运行期从 UIModel 提取。所以打印模板的"数据设计"更多是为了**通过发布检查**。

### 1.4 三种数据来源

`【社区】` `【实测】`

报表数据查询支持三种提供者类型：

| 提供者类型 | 说明 | 适用场景 |
|---|---|---|
| **`BusinessEntity`** | 采用**实体**建立报表 | 标准业务数据，**推荐**。可用实体字段自动带出业务含义 |
| **`StoredProcedure`** | 采用**存储过程**建立报表 | 复杂计算逻辑 |
| **`Text`** | 采用 **SQL 语句**建立报表 | 自由度高，**跨库查询**（可查其他数据库） |

> **⚠️ 注意区分两个"提供者类型"**：
> - **数据源**的提供者类型 → 选 `UFRPT`
> - **数据查询**的提供者类型 → 选 `BusinessEntity` / `StoredProcedure` / `Text`

### 1.5 与 UBF Studio 其他项目类型的关系

`【社区】`

| 简称 | 项目类型 |
|---|---|
| BE | 实体项目 |
| BF | 操作项目 |
| SV | 服务项目 |
| — | **分析项目** → 打印模板 |
| — | **报表应用项目** → 报表 |

## 2. 报表开发完整流程

`【实测】` 以下为完整实操流程。

```
1. 登录 UBF，切换到报表设计模式
2. 连接报表元数据库
3. 新建报表目录
4. 新建报表容器          ← 1 容器只能放 1 张报表
5. 创建报表
6. 设计数据源            ← 提供者类型选 UFRPT
7. 设计数据查询          ← BusinessEntity / StoredProcedure / Text
8. 字段扩展属性 + 布局设计
9. 添加查询条件（报表参数）★ U9C 报表必须有条件
10. 保存
11. 发布应用             ← 含菜单发布、程序集部署
12. 配置菜单权限
```

> **前置条件**：SSRS + UFRPT 已配置完成（见 `references/environment.md`）。

### 2.1 登录 UBF

1. 打开 UBF Studio
2. 点击**文件** → 找到**登录**
3. 如果没有显示"登录"，点击 **报表打印个性化切换**
4. 在"报表打印个性化切换"中选择对应的**企业和组织**登录

> 登录界面会出现**报表资源管理器**。

### 2.2 报表资源管理器

- 位置：在 UBF 的**右边**，或者点击工具栏 **查看** → 选择**报表资源管理器**
- 用于管理报表目录、报表容器的树形结构

### 2.3 连接报表元数据库

**报表元数据库是独立的**，与业务元数据库不同。

1. 点击**连接**
2. 选择**报表元数据库**
3. 找到 **`ReportRootCatalog`** 节点

> **`ReportRootCatalog`** 是报表资源树的根节点，所有报表都挂在它下面。

### 2.4 新建报表目录

1. 右键 `ReportRootCatalog` → **新建报表目录**
2. 输入任意名称（如 `KK`）
3. 显示为 `KK(用户自定义)`

### 2.5 新建报表容器 ⭐

1. 右键新建的报表目录 `KK` → 选择**新建报表容器**
2. 输入任意报表名称（如 `测试报表`）
3. 显示为 `测试报表(用户定义)`

> ⚠️ **重要规则**：**1 个报表容器下只能存放 1 张报表。每新建 1 张报表，需新建 1 个报表容器。**
>
> 这是新手最容易困惑的地方——不要把多张报表塞进同一个容器。

### 2.6 创建报表

1. 右键新建的报表容器 `测试报表` → 选择**创建报表**
2. 这里选择**报表**
3. 输入任意名称（**建议与报表容器保持一致**）

### 2.7 设计数据源

1. 默认显示"**布局**"页签，点击"**数据**"切换到数据源
2. 点击"**新增数据源**"
3. 点击"**添加数据源**"按钮，输入任意名称（如 `Db`）
4. **提供者类型选择 `UFRPT`** ⭐
5. 点击"**连接字符串**"右边的按钮
   - 演示用 `model`，**实际使用相应的 U9 数据库**
6. **连接串设置**：服务器选择实际的安装数据库名称 → 录入登录口令 → 选择相应的数据库

> **重要发现**：**U9 报表可以查询其他数据库**。
> 这意味着可以让 U9 报表直接读**数据仓库**（如 BigQuery 需通过 ODBC/链接服务器），或读取自定义的中间表/视图。

### 2.8 设计数据查询

1. 点击"**新增数据查询**"按钮
2. 输入任意名称（如 `DbQuery`）
3. **提供者类型选择 `Text`**（或 `BusinessEntity` / `StoredProcedure`，见 [第 4 章](#4-数据源与数据查询)）
4. **数据源选择**新添加的 `Db`
5. 输入 SQL 语句
6. 点击"**预览查询结果**"按钮验证

> **技巧**：**SQL 语句必须以 `;` 结尾**。如果字段面板显示的是 `Column1` 而不是真实列名，**将 SQL 语句以 `;` 结尾后重新预览数据即可**。

### 2.9 报表布局设计

1. 点击"**布局**"
2. 选择工具箱里的**报表控件** → 找到**表** → 拖拽到布局里的**明细**区
3. 点击工具箱里的"**字段**" → 显示数据源的列
4. 将工具箱里的字段**拖拽到表里的标题行位置**，同时**调整表头显示的值**

### 2.10 添加查询条件 ⭐⭐

> **U9C 报表必须有条件。**

这是官方文档反复强调的硬规则。**没有条件的报表打开后不显示任何数据。**

1. 点击工具栏"**报表**" → 选择"**报表参数**"
2. 在"报表参数"窗口**左边空白地方右键** → 选择"**添加条件项**"
3. 输入**名称**和**标签**
4. 针对**视图报表**，在**条件表达式**里选择**视图字段**

详细配置见 [第 6 章](#6-查询条件报表参数)。

### 2.11 保存

点击工具栏的**保存**按钮。

### 2.12 发布应用

1. 找到报表资源管理器中自己新建的**报表容器**
2. **右键** → 点击"**发布应用**"
3. 登录要发布的**企业和组织**
4. 检查：
   - **报表类型**：如果显示的不是"用户定义"而是"系统定义"，说明**存在 UBF 安装问题或者文件不全**
   - **用户程序集部署**：如果显示的不是自己的电脑，说明**报表服务器未配置正确**

### 2.13 添加菜单

在发布应用向导里操作：

1. 选择"**菜单发布**"
2. 选择需要发布的**菜单位置**
3. 点击"**新建**"按钮
4. 输入自定义名称（如"开发报表"）
5. 选择刚刚创建的菜单，再点击"**新建**"按钮，**创建子菜单**
6. 选择当前创建的子菜单，点击"**绑定菜单**"按钮
7. 在下一步的"**部署任务**"里，点击"**执行**" → **执行成功也就发布完成**

### 2.14 添加用户报表权限

1. 登录 U9C
2. 找到 **系统管理** → **菜单权限**
   - **模块**：就是发布报表时创建菜单的位置
   - **角色**：用户拥有的角色
3. **退出 U9C，重新登录**
4. 在相应模块下看到当前发布的报表

> **验证现象**：打开开发的报表时，如果**不显示任何数据**——这是正常的，**因为报表必须要有条件**。填入条件后即显示数据。

## 3. 数据源与数据查询

### 3.1 数据源配置

| 配置项 | 值 |
|---|---|
| 名称 | 任意（如 `Db`） |
| **提供者类型** | **`UFRPT`** |
| 连接字符串 | 通过向导配置：服务器名 + 口令 + 数据库名 |

**连接技巧**：`【社区】`

> **server name 里直接输入数据库服务器 IP 地址，比点下拉三角选择快得多。**

### 3.2 方式 A：`Text`（SQL 语句）

`【实测】` `【社区】`

**步骤**：

1. 数据源同 [3.1](#31-数据源配置)
2. 数据查询的**提供者类型选择 `Text`**
3. 编写 SQL 语句
4. 点击"**预览查询结果**"→ 下方窗口显示查询结果，左边"**字段**"窗口显示 SQL 中选择的字段

**技巧**：

- 可以先编写 **OQL 语句**，再**翻译成 SQL 语句**，将编译成功后的 SQL 复制到窗口中
- **SQL 必须以 `;` 结尾**，否则字段面板显示 `Column1`

### 3.3 方式 B：`BusinessEntity`（实体）

`【社区】`

**步骤**：

1. 新建报表容器、报表
2. 连接数据源（技巧：server name 直接输入 IP）
3. 增加数据查询
4. **选择实体**（可以选择，也可以选择"**查找实体**"，**使用查询实体会更快一点**）
5. **选择需要的字段** → 点击保存后字段即出现在左边的"字段"栏目中
6. 可以点击 UBF 自带的**查询功能来预览数据**
7. 可以用 UBF 自带工具**翻译成 SQL 语句**到 MSSQL 查询里面去查询

> **OQL 说明**：**OQL 语句支持 SQL 语句的格式**，可根据 SQL 语句格式自动编辑。

**⭐ 强烈推荐的用法：BE 实体查询当数据字典用**

用 BE 实体建立报表时可以直接查实体字段。实际做报表时这个功能用得少，但**用来当数据字典非常高效**：

- **A.** U9 数据库更新频繁，但**数据字典不能及时更新**，有时会出现数据字典中找不到字段的情况
- **B.** BE 实体**查字段速度快且效果直观**
- **C.** 只有需要知道字段意义时才需要翻数据字典，而这个方法可以省略

**配套技巧：用 F12 抓字段名**

用浏览器打开 U9 单据页面，用 **F12 开发者工具就能捕捉到对应的字段名称**。**前台字段名称与后台字段名称是相同的**，非常方便。

> **这两个技巧的组合价值**：**这是绕开"拿不到物理表 DDL"困境的实用替代方案**——通过 BE 实体查询 + F12 反查，可以定位到具体字段及其业务含义，无需等待数据字典。详见 `references/api-dto.md`。

### 3.4 方式 C：`StoredProcedure`（存储过程）

采用存储过程建立报表。适用于复杂计算逻辑。

> **本项目规范提醒**：存储过程应仅用于**超复杂批量统计、多表聚合、高频固定报表**。简单查询、单表操作**不应**写存储过程。

### 3.5 视图报表

`【社区】`

> 针对视图报表，在**条件表达式**里选择**视图字段**。

说明 U9 报表可以基于**视图**建立。视图报表的条件配置走"视图字段"。

> **对打通数仓的意义**：如果能在 U9 库里创建**视图**，视图的列名可以自行定义，**就不受物理表列名限制**。

## 4. 字段扩展属性

`【社区】`

选中数据查询后，可为字段设置扩展属性。

### 4.1 栏目属性（三个互斥/叠加的开关）

| 属性 | 效果 |
|---|---|
| **备选栏目** | 发布后在报表查询方案的栏目字段中显示在"**待选项**"列表中 |
| **固定栏目** | 显示在"**已选项**"列表中 |
| **默认栏目** | 系统默认显示在"**已选项**"列表中 |

**组合规则**：

| 组合 | 效果 |
|---|---|
| 备选栏目 + 固定栏目 | 字段**用户无法从"已选项"中移去**（此字段为**必选项**） |
| 备选栏目 + 默认栏目 | 字段**默认显示在"已选项"中，但用户可以自行移去** |
| 备选 + 固定 + 默认 | 与"备选栏目 + 固定栏目"的效果**相同** |

> **设计建议**：
> - 关键字段（如单据号、日期）→ 备选 + 固定（必选）
> - 常用字段 → 备选 + 默认（默认显示但可移除）
> - 次要字段 → 仅备选（用户需要时手动添加）

### 4.2 行分组

支持设置**行分组**，用于报表的行级汇总。

## 5. 查询条件（报表参数）

> ⭐ **U9C 报表必须有条件。没有条件，报表打开后不显示任何数据。**

### 5.1 添加条件项

`【实测】` `【社区】`

1. 选择菜单上的"**报表参数**"建立查询条件
2. 在弹出的报表参数设置窗口中，**左边点击右键** → "**添加条件项**"
3. 在"**基本属性**"页签中点击 **`fx`**，选择**条件表达式**
4. 点击"**参照**"页签，选择该条件的相应字段
5. 输入**名称**和**标签**

### 5.2 条件项的三个开关

| 开关 | 含义 | 说明 |
|---|---|---|
| **允许为空** | 选择后，此查询条件**可以不输入** | 不选择则为**必输项** |
| **是否可见** | **不出现**此字段 | 隐藏的条件（可用于传递固定参数） |
| **是否固定条件** | 此条件字段**不可删除**（一定要使用此字段） | 用户可以设置成无需输入，但根据实际情况这样无意义，**设置成固定字段肯定是必输项** |

### 5.3 参照设置

参照页签可以设置多种参照方法：

| 参照类型 | 说明 |
|---|---|
| `nothing` | 表示无 |
| `reference` | 可以设置参照值 |
| **实际 ID** | 选择参照的**实体** |
| **参照 ID** | 选择一个"类型样子"的参照即可（**可理解为当作模型使用**） |

### 5.4 ⚠️ 关键坑：必须"添加默认"

`【社区】` 原文：

> 建立完查询条件后，**到报表主页上"数据"页签中，修改数据查询**。在**查询参数**页签上，点击"**添加默认**"按钮，确认退出。
> **如不操作，查询条件将不起作用。**

**这是最容易踩的坑**——你明明配好了查询条件，但报表运行时条件无效。原因就是漏了这一步。

**完整操作路径**：

```
报表参数（配置条件项）
      ↓
数据 页签 → 修改数据查询
      ↓
查询参数 页签 → 点击「添加默认」→ 确认退出
      ↓
条件生效
```

## 6. 报表布局设计

### 6.1 基本操作

`【实测】`

1. 点击"**布局**"页签
2. 选择工具箱里的**报表控件**
3. 找到"**表**"控件 → 拖拽到布局里的**明细**区
4. 点击工具箱里的"**字段**" → 显示数据源的列
5. 将字段**拖拽到表里的标题行位置**
6. **调整表头显示的值**（表头文本可自定义）

### 6.2 报表属性

`【社区】`

> 用户可以利用右边的**报表属性**进行调整报表的样式。

### 6.3 布局设计原则

| 要点 | 说明 |
|---|---|
| 数据源列 → 表头 | 字段拖到标题行，表头文本可改 |
| 明细区 | 拖入"表"控件后自动生成明细行 |
| 样式 | 通过报表属性面板调整 |
| 字段顺序 | 按拖拽顺序排列，可调整 |

## 7. 发布与权限配置

### 7.1 发布前检查

`【实测】`

| 检查项 | 期望值 | 异常含义 |
|---|---|---|
| 报表类型 | **用户定义** | 若显示"系统定义" → **UBF 安装问题或文件不全** |
| 用户程序集部署 | **自己的电脑** | 若显示别的 → **报表服务器未配置正确** |

### 7.2 发布流程

```
报表容器 右键 → 发布应用
      ↓
登录企业和组织
      ↓
菜单发布 → 选择菜单位置 → 新建菜单 → 新建子菜单 → 绑定菜单
      ↓
部署任务 → 执行
      ↓
执行成功 = 发布完成
```

### 7.3 权限配置

1. 登录 U9C
2. **系统管理** → **菜单权限**
   - **模块** = 发布报表时创建菜单的位置
   - **角色** = 用户拥有的角色
3. **退出 U9C，重新登录**
4. 在相应模块下看到当前发布的报表

### 7.4 验证

| 现象 | 说明 |
|---|---|
| 打开报表**不显示任何数据** | **正常**——报表必须要有条件 |
| 填入条件后显示数据 | 配置正确 |

## 8. 打印模板开发

`【社区】` 引自《U9研发体系（打印开发手册）》（U9-UBF-001 V1.0，124 页）

### 8.1 与报表的关系

- **UBF Studio 的报表开发工具既可以设计报表，也可以设计打印模板**
- 打印模板设计分两大部分：**数据设计** + **布局设计**

### 8.2 数据设计

> **数据设计对打印模板并不如报表那样重要**，因为**打印数据生成不是由打印引擎完成，而是由开发人员在运行期根据当前 UIModel 提取出来的**。
>
> 但因为**打印模板发布检查模型完整性**，如果不进行数据设计，**发布时会报错**。

### 8.3 导出服务（EXPORTSERVICE）

U9 的打印/导出由 **应用导出服务组件（EXPORTSERVICE）** 承担。

**核心 API**：

```csharp
IExportSettings settings =
    ExportServiceFactory.GetInstance().CreateExportSettingsObject();
```

**可用设置项**：

| 设置项 | 作用 |
|---|---|
| `settings.ColumnsWidth` | 列宽。如不设，取系统默认 200 像素。开发人员可参考当前列表 DataGrid 的对应列列宽 |
| `settings.ColumnsAlignment` | 每列的布局方式（`TextAlignment.Left` / `Center` / `Right`）。如不设，根据 DataTable 对应数据类型获取默认布局 |
| `settings.Title` | 标题。如不设，取默认值"列表打印" |
| `settings.TileAlignment` | 标题布局。如不设，居中显示 |
| `settings.UIDataGridName` | 设置 DataGrid 的名称 |
| `settings.PrintData` | 传递的打印数据 |
| `settings.FileName` | 导出文件名前缀。系统默认取当前主 View 的名称作为导出文件名的前缀 |
| `settings.OnlyCurrentPageData` | 只打印当前 DataGrid 数据内容 |
| `e.Tag = settings;` | 将设置挂到事件参数上 |

### 8.4 打印的两类场景

**列表或查询打印**——支持的操作：

- 台头、标题布局、用户标题的设置
- 隐藏用户标题
- 传递默认 DataGrid 名称
- 打印数据
- 导出文件名设置
- **含自定义列的 DataGrid 输出与打印**
- **当前 DataGrid 数据打印**

**单据打印**——探讨列表打印的**适用范围和局限性**，介绍完整打印流程，强调打印模板设计的重要性。

### 8.5 ⚠️ 含自定义列的 DataGrid 打印坑

`【社区】`

**问题**：

> 默认列表打印与输出数据输出为**当前列表内容对应的全部数据内容，非当前页内容**。因此数据要通过 **UIVIew 对应实体的 OQL 重新从数据库中读取**，这种情况会使**自定义列内容不能显示**（因为 **OQL 中不包含自定义列**）。

**两种解决办法**：

1. **用户在运行期组织数据 DataSet**（参考"传递打印数据"）

```csharp
IExportSettings settings =
    ExportServiceFactory.GetInstance().CreateExportSettingsObject();
settings.PrintData = /* 自行准备原始打印数据 */;
settings.UIDataGridName = "DataGrid0";
e.Tag = settings;
```

> 适用于：**列表含自定义列同时数据又有多页的情况**
> 注意：传递的打印数据为**原始数据**，具体显示还要根据当前列表中的 DataGrid 进行过滤和转换（如枚举值为数据、布尔类型为 true/false，需要根据列表中的枚举列进行显示转换）。格式也要根据当前列表中列样式进行设置（如列宽、列显示名称）。

2. **只打印当前 DataGrid 数据内容**

```csharp
settings.OnlyCurrentPageData = true;
```

> 适用于：**当前 DataGrid 显示了所有该显示的数据**

### 8.6 打印模板相关设置

`【官方】` `【实测】`

- 可以直接在系统提供的打印模板基础上**调整存为自己的打印模板**
- 也可以**完全自定义打印模板**
- 相关官方手册：`打印个性化.PDF`、`U9Cloud 用户操作手册--打印模板工具易用性改进.docx`

## 9. 常见问题与坑

### 9.1 高频坑清单

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | **报表没有查询条件** | 打开报表不显示任何数据 | 必须加查询条件（[2.10](#210-添加查询条件-)） |
| 2 | **配了条件但不生效** | 条件配置了，运行时无效 | 漏了"数据 → 修改数据查询 → 查询参数 → **添加默认**"（[5.4](#54--关键坑必须添加默认)） |
| 3 | **SQL 没以 `;` 结尾** | 字段面板显示 `Column1` | SQL 以 `;` 结尾后重新预览 |
| 4 | **一个容器塞多张报表** | 报表冲突/丢失 | **1 容器只能放 1 张报表**（[2.5](#25-新建报表容器-)） |
| 5 | **UFRPT 未注册** | 数据源选不到 `UFRPT` | 编辑 `rsreportserver.config` |
| 6 | **没切报表设计模式** | 界面上找不到报表菜单 | `IDEConfig.xml` 设为 `True`（[1.2](#12-报表设计器能力)） |
| 7 | **报表类型显示"系统定义"** | 无法正常发布 | UBF 安装问题/文件不全 |
| 8 | **程序集部署不是本机** | 发布异常 | 报表服务器（SSRS）未配置正确 |
| 9 | **报表程序集加载失败** | "未能加载文件或程序集" | 补齐 DLL 到 SSRS 的 `ReportServer\Bin` |
| 10 | **自定义列打印不显示** | 含自定义列的列表打印缺列 | 见 [8.5](#85--含自定义列的-datagrid-打印坑) |

### 9.2 排查工具

| 工具 | 用途 |
|---|---|
| **Everything** | 秒搜文件，解决"缺 DLL"类问题 |
| **浏览器 F12** | 反查页面字段名（前台字段名 = 后台字段名） |

## 10. 与数据仓库的衔接

### 10.1 三条打通路径

U9C 报表支持查询**其他数据库**（[2.7](#27-设计数据源)），这为 U9 报表与数据仓库打通提供了三条路径：

| 路径 | 做法 | 适用 |
|---|---|---|
| **A. U9 报表读数仓** | 数据源连接串指向数仓（需 ODBC/链接服务器），数据查询用 `Text` 写 SQL | 报表口径统一由数仓提供，**推荐** |
| **B. 数仓读 U9** | 数仓 ETL 从 U9 库抽取（需物理表名） | 传统数仓模式 |
| **C. 视图中转** | 在 U9 库建视图，视图列名自定义，U9 报表基于视图 | 规避物理表列名限制 |

### 10.2 与 DTO 字段清单的配合

DTO 字段清单（见 `references/api-dto.md`）在报表开发中能帮上什么：

| 报表开发环节 | DTO 清单能帮上吗 | 说明 |
|---|---|---|
| 设计数据源连接串 | ❌ | 需要物理连接信息 |
| 写 SQL（需物理表名/列名） | ❌ | 只有 DTO 属性名 |
| 用 `BusinessEntity` 方式选实体字段 | ✅ **部分** | 实体名/属性名可参考 |
| 理解字段业务含义 | ✅ **强** | 中文含义覆盖率：销售 87%、采购 89%、库存 92% |
| 设计查询条件的业务筛选值 | ✅ **强** | 枚举值可直接复用（如单据状态 0开立/1审核中/2已审核） |
| 设计栏目扩展属性 | ⚠️ 参考 | 参考字段的业务重要性排序 |

### 10.3 关键约束提醒

| 约束 | 说明 |
|---|---|
| **物理表名仍缺** | DTO 清单无表名。走路径 B 需先拿到物理 schema；走路径 A/C 可规避 |
| **仅覆盖已开放接口的模块** | DTO 清单只含 `服务可见 = True` 的属性。报表若需读取不可见字段，DTO 帮不上 |
| **弹性域字段不可见** | 弹性域在 DTO 层统一表现为 `DescFlexFieldRData`，看不出实际内容 |
